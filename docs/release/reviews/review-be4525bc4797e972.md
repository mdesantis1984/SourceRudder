## Legacy header guard

Any line starting with `Authority:` anywhere in the receipt body
is rejected by both the bash gate (`scripts/release-gate.sh`) and
the Go process guard (`internal/mcp/release_gate_test.go`). A
future regression that smuggles the legacy external-binding
header back through only one of the two validators MUST fail the
other.

## Rollback honesty

The precise `Candidate Commit` contract makes the receipt
non-rogue across the two rollback paths:

- **Atomic `git revert`**: the rollback commit's receipt still
  has the buggy SHA as its `Candidate Commit`, but the buggy
  SHA is now HEAD~2 or deeper of the rollback commit, so the
  gate fails and forces a fresh receipt that points to the
  rollback commit.
- **New code commit on top**: a follow-up commit moves the
  receipt's `Candidate Commit` to HEAD~2 or deeper of the new
  HEAD, so the gate fails and forces a fresh receipt.

In both cases the operator MUST author a new receipt (a
"recovery receipt" companion or a re-authored main receipt) and
the `Status: pass` line MUST NOT be silently carried forward.
