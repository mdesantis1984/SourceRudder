(receipt-driven development) evidence contract for the
`close-fetch-resilience-and-release-gates` change. The release
gate at `scripts/release-gate.sh` parses this receipt on every

This contract REPLACES the previous `Authority: official` header

review provider binding — a contract that could not be satisfied

`go build` / `go vet` / `go test` / `go test -race` so a forged
receipt cannot bypass a real regression.

## Field contract (parsed by the gate)

| Field | Required form | What the gate checks |
|-------|---------------|----------------------|
| `Status:` | exact line `Status: pass` | Anything else (pending, fail, foo, blank) blocks merge. |
| `Candidate Commit:` | full 40-char SHA reachable from HEAD | The SHA must be an ancestor of (or equal to) HEAD. A receipt created at one commit remains valid for any descendant HEAD. |
| `Scope:` | line that mentions the current branch name | The branch token (e.g. `feature/close-fetch-resilience-release-gates-exception`) must appear in the Scope value. A receipt authored for one branch cannot unlock a merge on a different branch. |
| `Verified Commands:` | section header followed by one or more `  - <cmd>: PASS` lines | Every entry must end with `: PASS`; any `: FAIL` or absent result blocks the merge. |
| `Unresolved Blocker Policy:` | present (value free-form) | The operator MUST declare or waive any unresolved blocker. The header itself is the assertion; the value text is documentation. |

## Lifecycle

| State | Field value | Gate behavior |
